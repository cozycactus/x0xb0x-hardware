# KiCad working revision 26 — SIP9 pads and name labels restored

Revision 26 corrects the two conversion differences that revision 25's fabrication comparison recorded on copper and silkscreen. It changes no drill, track, via, net, zone, footprint pose, model or schematic.

**SIP9 pads (mainboard IC14, IC15A, IC15B — 27 pads, and the library footprint's 9).** The Eagle library pads are "long" with a 1.016 mm diameter on a 0.9 mm drill. Eagle 4.13 first restrings the diameter to 1.408 mm (0.9 + 2 × rlMinPadTop 0.254), then elongates it 100 %, so its CAM output is 1.408 × 2.816 mm. The importer had elongated the library diameter instead (1.40 × 2.032 mm). Only the pad `size` node changes, to `(size 2.816 1.408)`. The mask opening follows through the unchanged 0.1016 mm margin.

**Name labels (381 mainboard, 80 I/O).** Each label now takes its position, rotation, layer and size from the element's Eagle smashed name record, instead of the library `>NAME` default. Rotation and justification follow KiCad's own Eagle importer rule (`EaglePcbTextToKiCadAlignment`): Eagle turns text past 90° so it stays readable, which KiCad represents as the opposite angle anchored at the top-right corner. The record stores half the text size, as Eagle's text record does (`half_size`), and the conversion's staging XML does not double it. The production I/O photograph (`../models-review-10/heatsink-fit-research/sources/ioboard_done.jpg`) shows the J3 name at the same height as the J3 package's 1.27 mm "1"/"12". With the size doubled, every label keeps its previous size except I/O C3 and C5 (1.778 → 1.27 mm). The 11 references KiCad must end with "0" keep their reference, now hidden, and print the Eagle name through a footprint text: IC15A, IC15B, R100A, R100B (mainboard); CV, GATE, POWER, USB, MIXOUT, MIXIN, HEADPHONE (I/O).

`install_sip9_pads_and_name_labels.py` replaces the pad sizes as text and copies only the Reference property nodes, plus the 11 new texts, from a temporary board that `apply_name_records.py` sets through KiCad's API. `installation-audit.json` records the hashes, counts and every label row. `verify_name_labels.py` then checks every printed label against its record, and checks the anchor corner of KiCad's text box against Eagle's readability rule written out independently. All 461 labels pass; the largest corner offset is 0.204 × text size, which is the descender space in KiCad's box.

Results:

- **Gerber comparison** (`fabrication-comparison/`, revision-25 scripts re-run): all 1209 mainboard pads now match Eagle on both copper layers; mask differences are down to the seven NPTH stop frames; every silkscreen text (345 + 166 mainboard, 87 + 1 I/O) sits on its Eagle anchor with the Eagle name. Via tenting and the IC25 mask corners remain as recorded.
- **Fresh KiCad 10.0.7 ERC/DRC:** ERC 0/0 on both boards. Every non-silkscreen DRC violation (48 mainboard, 7 I/O) is identical item by item to revision 25, and schematic parity, ignored checks and the two GND splits are unchanged. Silkscreen warnings drop from 448 to 335 (mainboard) and from 348 to 269 (I/O): mainboard overlaps 199 → 88, edge clearance 2 → 0; I/O overlaps 95 → 17, edge clearance 47 → 46. KiCad reports at most 199 items of one type, so `silk_over_copper` (199 on each side) is compared by count only. A direct check finds no silkscreen on the longer SIP9 pads (revision 25 had four library-position labels there); the nearest silk is the SIP9 outline, 0.03 mm from the pad ends. Two I/O overlaps are new at the original positions: R12's name over the XTL2 outline, and C8's name over J5's "1".
- The DIN function proof replays unchanged (214 checks) with the I/O PCB hash carried forward (`update_function_evidence.py`). Local libraries and models resolve exactly as in revision 25. The Blender scene has no silkscreen and is unchanged.
